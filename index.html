會議之後的斷層

會議結束，工作卻變得模糊。

一場 45 分鐘的會議，可以產生十個承諾。但它們通常只留在筆記、聊天群組，或某人的記憶裡。

01

決定消失無蹤

「為什麼」在週末前就被埋在錄音裡。

02

負責人含糊不清

大家都點頭，但沒有人肯定下一步由誰負責。

03

工具各自為政

同一件事要被抄進三個系統，然後慢慢無人跟進。

Relay 把對話到完成之間的循環接回來。

RELAY 如何運作

四步，由「我們應該」走到「已經完成」。

保留人手審核，移除抄寫與追問。Relay 負責把會議裡的工作整理好，你只需要確認。

01

把會議帶進來

上載錄音、貼上逐字稿，或連接會議來源。

02

Relay 找出真正的工作

按講者分析承諾、負責人、期限與決定。

03

你審核整個交接

在建立任何任務前，修改內容、剔除雜訊、確認目的地。

04

任務直達你的工具

Notion、Jira、Trello 收到有編號、有負責人的結構化記錄。

人手審核是內建步驟，不是附加功能 一個審核畫面，處理所有目的地。

為真正跟進而設

由「我們應該」到「已經完成」之間的一切。

Relay 不只做摘要。它處理承諾、負責人、期限、規則與交付。

按講者分配負責人

利用逐字稿的講者標籤，把「我會做」對應到人；低信心的配對會標示出來待你確認。

真正可用的期限

「星期五前」、「聽日」、「下星期二」會按會議日期換算成真正的期限，而不是留低一句模糊文字。

預設由人手批准

未經你批准，任何任務都不會送出。你可以剔除雜訊，只留下真正的工作。

看得見的規則

緊急工作送到 Jira、法律文案送到 Notion、社交素材送到 Trello；任何規則都可以隨時暫停。

有紀錄，不靠估

每項已路由的任務都有外部編號、目的地、負責人與狀態，交接有憑有據。

為開發者而設

Webhook API、Zapier 事件、冪等寫入與重試機制，讓自動化可靠地運行。

常見問題

試用之前，先看清楚。

關於 Relay 最常被問到的問題。

打開示範
示範真的連接到 Notion、Jira、Trello 嗎？

不是。示範中的寫入是模擬的，讓你毋須連接帳戶也能試完整流程；正式版的連接器設計寫在 README。

Relay 會自動加入會議嗎？

示範接受錄音或逐字稿；正式版可連接 Zoom、Google Meet 或 Fireflies 的 webhook。

我可以修改抽取出的行動嗎？

可以。標題、負責人、期限、優先級與目的地都可以在路由前修改。

我的逐字稿會去哪裡？

在這個示範中，逐字稿只留在你的瀏覽器，不會上載；正式環境的憑證與處理都留在伺服器端。

上載錄音真的會用 Whisper 嗎？

靜態示範不會。上載流程是模擬的，會用樣本逐字稿進行抽取；README 說明了 Whisper／Deepgram 在正式架構中的位置。

這是誰做的？

網站如何部署？

每次合併到 main 都會觸發 GitHub Actions，自動重新部署 GitHub Pages。
